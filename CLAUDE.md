# CLAUDE.md — сайт ИФК «Дина» (Москва)

Ты работаешь над сайтом исторического футзального клуба «Дина». Работай **автономно**: владелец проекта не отвечает на вопросы во время сессии. Если не хватает решения — прими разумное решение сам, запиши его в `PROGRESS.md` в раздел «Решения, принятые без владельца» и продолжай. Не останавливайся ради вопросов.

## 1. Суть проекта

У клуба сейчас нет профессиональной команды. Это **не** сайт действующего клуба: никаких календарей, турнирных таблиц, билетов, магазина, составов. Это компактный премиальный сайт-наследие: масштаб клуба → история → титулы → легенды → место в истории российского футзала → возможность продолжения.

Главная мысль: **«Команды сегодня нет. История — есть. И она огромна.»** Честно, но не грустно. Сайт должен выглядеть так, будто за ним стоит большой спортивный бренд.

Посетитель-болельщик должен подумать: «Я и забыл, насколько большой была «Дина»». Новый посетитель: «Почему я раньше не знал об этом клубе?»

## 2. Жёсткие правила контента

1. **Все факты берутся только из `content/*.json`.** Не придумывай даты, цифры, титулы, биографии, цитаты, годы в клубе. Не дополняй факты из своей памяти и из интернета.
2. Поле со значением `null` означает «не подтверждено». Такое поле **не выводится** на сайт. Не подставляй вместо него заглушки вроде «1990-е».
3. Тексты из `content/` можно сокращать под вёрстку, но нельзя менять их смысл и добавлять новые утверждения.
4. Интерфейсные тексты (кнопки, подписи, ошибки, мета-описания) пиши сам: по-русски, простыми словами, в активном залоге. Кнопка говорит, что произойдёт: «Отправить сообщение», а не «Submit».
5. Название клуба выводится **только** из `content/club.json` → `displayFullName` и `shortName`. Название ещё не подтверждено (ИФК или ИСК), поэтому нигде не хардкодь его в компонентах.
6. Реквизиты и контакты сейчас `null`. Вёрстка должна корректно работать без них: блок не показывается, а не показывает пустоту.

## 3. Стек

- **Next.js** (последняя стабильная, App Router), **TypeScript** strict, **React Server Components** по умолчанию.
- **Tailwind CSS v4** с CSS-переменными-токенами (раздел 5). Без UI-китов, кроме точечных доступных примитивов при реальной необходимости (диалог для лайтбокса можно сделать самим на `<dialog>`).
- **Motion** (`motion/react`) — только для оговорённых анимаций (раздел 6).
- **Zod** — схемы для всего `content/*.json`; загрузчик в `src/lib/content.ts` валидирует данные при сборке и падает с понятной ошибкой на русском.
- **Nodemailer** — отправка формы на email через SMTP (Server Action).
- **next/font/google** — шрифты самохостятся при сборке (никаких запросов к Google у посетителя).
- **next/image** — AVIF/WebP, адаптивные размеры, lazy loading ниже первого экрана.
- **Playwright** + **@axe-core/playwright** — e2e, доступность, скриншоты для самопроверки.
- **@lhci/cli** — Lighthouse CI.
- ESLint + Prettier.
- Сборка `output: 'standalone'`, деплой — Docker на российском VPS (раздел 9).

Инициализация: папка уже содержит файлы, поэтому `create-next-app` запускай во временной папке `./_scaffold` и переноси результат в корень, не затирая существующие файлы (`CLAUDE.md`, `content/`, `docs/`, `public/`, `.claude/`). Потом удали `_scaffold`.

## 4. Структура сайта

| URL | Страница | Содержимое |
|---|---|---|
| `/` | Главная | 8 блоков, см. ниже |
| `/istoriya` | История | Hero, вступление, таймлайн из 7 этапов, трофеи |
| `/lyudi` | Люди | Легенды + блок «Из «Дины» — в большую игру» |
| `/foto` | История в фотографиях | До 20 кадров, лайтбокс, подписи |
| `/klub` | Клуб и контакты | О клубе, «Дина сегодня», форма, контакты, реквизиты |
| `/politika` | Политика конфиденциальности | Шаблон по 152-ФЗ с плейсхолдерами оператора |
| 404 | Не найдено | В фирменном стиле, ссылка на главную |

Отдельные страницы игроков **не делать** (V2).

### Главная — 8 блоков

1. **Hero.** Полноэкранное архивное фото (слот `hero-main`), огромное слово-«призрак» «ДИНА» позади заголовка, полное название, слоган из `club.json → tagline`, одна кнопка «История клуба».
2. **Масштаб.** Большие цифры из `trophies.json` (`featured: true`). Крупная типографика, не таблица и не карточки.
3. **История коротко.** 2–3 абзаца из `club.json → historyIntro`, 3 фото разных эпох, кнопка «История «Дины»».
4. **Легенды.** 6 вертикальных фото-карточек (`people.json → legends`, `featured: true`), подпись поверх фото, кнопка «Все легенды». Это референс карточек с сайта ФК «Барселона»: вертикальный кадр, имя крупно внизу.
5. **«Дина» сегодня.** Текст из `club.json → today`. Честно, спокойно, с достоинством.
6. **Из «Дины» — в большую игру.** 3 человека из `people.json → alumni`, компактно: фото, имя, связь с клубом, чем известен.
7. **Фото-панно.** 6–8 лучших кадров из `photos.json` асимметричной сеткой, кнопка «Смотреть историю в фотографиях».
8. **Финал.** Большой логотип, полное название, слоган, контакты (если есть), форма-ссылка на `/klub#napisat`.

### Архитектура «под возвращение» (V2/V3)

Не реализуй, но не мешай будущему добавлению разделов: текущий состав, тренер, календарь, матчи, результаты, новости, билеты, магазин, академия, партнёры. Навигация строится из одного конфига `src/config/nav.ts`; контент лежит в отдельных JSON-сущностях.

## 5. Дизайн-система (направление «Возвращение», согласовано владельцем)

Визуальный код: **SPORT × HERITAGE × PREMIUM × EDITORIAL**. Тёмный, глубокий, полноэкранные фото, крупная сжатая типографика, большие цифры, много воздуха. Не музей и не шаблон футбольного клуба.

### Цвета (из герба и клубных жёлто-зелёных шарфов)

```css
--night:   #0A0F1E;  /* основной фон */
--night-2: #121A2F;  /* приподнятые поверхности */
--ivory:   #EEE9DF;  /* основной текст */
--mist:    #9AA3B5;  /* вторичный текст (проверь контраст ≥ 4.5:1 на --night) */
--pushkar: #F2C21B;  /* жёлтый «пушкарей»: цифры, акценты */
--field:   #1E8C45;  /* зелёный */
--shield:  #1F4FBF;  /* синий */
--crown:   #C9A24B;  /* золото короны: главная кнопка, «императорские» моменты */
```

Жёлтый и зелёный — клубные цвета. Синий участвует только в полосе-подписи (ниже). Золото используется редко: главная кнопка, полное название в hero и футере.

### Типографика

- **Fira Sans Extra Condensed** (800, 500) — заголовки, цифры, слово-«призрак». Заголовки H1/H2 — прописными, плотный трекинг. Большие цифры — 800.
- **Golos Text** (400, 500) — основной текст. Кириллица, хорошая читаемость.
- Только эти два семейства. Подзаголовки-«брови» над секциями **не** делать прописными с разрядкой: обычный регистр или вообще без них.
- Модульная шкала, длина строки текста ≤ 70 знаков, межстрочный 1.6 для основного текста.

### Фирменные элементы (смелость — только здесь)

1. **Диагональная полоса** синий/жёлтый/зелёный под углом примерно −18°, как на щите герба. Используется максимум 3 раза за страницу: низ hero, переход к «Дина сегодня», футер. Это главный узнаваемый элемент.
2. **Слово-«призрак»**: огромный текст «ДИНА» (или год на странице истории) цветом чуть светлее фона позади заголовка, как в референсе Барсы с OCTOBER.

Всё остальное — тихое: никаких градиентных подложек, теней под каждой карточкой, одинаковых скруглённых карточек везде, разделителей с точками «·», стрелок «→» в кнопках.

### Фото

- Архив до 2010 года: ч/б, слегка тонированный в сторону `--night` (CSS-фильтр или подготовка при сборке), лёгкое зерно допустимо.
- 2012 и позже: цветные, приглушённая насыщенность.
- **Фото пока нет.** Компонент `<ArchivePhoto slot="…">` берёт файл по `photos.json`. Если файла нет, рисуется **типографический фолбэк**: тёмная панель `--night-2`, год или эпоха огромными цифрами, тонкая полоса цветов. Сайт должен выглядеть законченным без единой фотографии. Никаких серых квадратов «Фото будет позже» в продакшене.

### Логотип

`public/brand/logo-full.png` — растр 1024×1536 с сильной детализацией.

- Крупно (hero, финальный блок, 404) используй как есть через `next/image`.
- В шапке — компактный вордмарк: «ДИНА» шрифтом Fira Sans Extra Condensed 800 цветом `--pushkar` плюс герб высотой не меньше 40px (на ретине из оригинала).
- Фавикон и apple-touch-icon — монограмма «Д» цветом `--pushkar` на `--night`. Сгенерируй SVG и PNG через `sharp`. Герб на 16px не читается.

## 6. Движение и UX

- Одна оркестрованная сцена загрузки hero: проявление фото, въезд слова-«призрака», прорисовка полосы. Всего не больше 1,2 с.
- Цифры в блоке «Масштаб» досчитываются один раз при появлении в зоне видимости.
- Больше никаких анимаций появления секций. Hover на карточках легенд — лёгкое увеличение фото, без подпрыгивания.
- `prefers-reduced-motion` отключает всё, кроме переходов состояния.
- Лайтбокс: `<dialog>`, свайп на мобильном, стрелки и Esc на десктопе, подпись, счётчик «3 из 20», фокус-ловушка.
- Мобильная версия — в приоритете (mobile-first): hero, цифры, таймлайн, фото и меню на телефоне должны выглядеть даже сильнее, чем на десктопе. Меню — полноэкранный оверлей.
- Видимый фокус клавиатуры, контраст AA, семантическая разметка, `lang="ru"`.

## 7. Форма обращения (`/klub#napisat`)

- Поля: имя, email, тема (Партнёрство, СМИ, Архивные материалы, Другое), сообщение, чекбокс согласия на обработку персональных данных со ссылкой на `/politika`.
- Server Action → Zod-валидация → Nodemailer по SMTP из env. Ошибки — у поля, на русском, по делу.
- Защита от спама: скрытое поле-ловушка, минимальное время заполнения 3 с, лимит 5 отправок в час с одного IP (в памяти процесса — допустимо для одного инстанса).
- Если SMTP не настроен (`SMTP_HOST` пуст), письмо пишется в лог сервера, а пользователю показывается успех. Сборка и e2e не должны требовать SMTP.
- Секреты только в `.env` (см. `.env.example`). Не читай и не выводи `.env`.

## 8. SEO

- Для каждой страницы: `title`, `description`, `canonical`, Open Graph, Twitter card. OG-картинки генерируются через `next/og` со шрифтом с кириллицей.
- Целевые запросы: «Дина футзал», «Дина Москва футзал», «МФК Дина», «ИФК Дина», «Императорский клуб Дина», «Дина чемпион России», «Дина футзал история», «Дина Москва игроки», «Дина Москва титулы».
- H1 — один на страницу.
- `sitemap.xml`, `robots.txt`, хлебные крошки на внутренних страницах (+ `BreadcrumbList`).
- Schema.org: `SportsOrganization` / `SportsTeam` (название из `club.json`, `foundingDate`, `sport: "Futsal"`, `location`), `Person` для легенд на `/lyudi` (только подтверждённые поля).
- `NEXT_PUBLIC_SITE_URL` из env; без него — `http://localhost:3000`.
- Яндекс.Метрика: подключается, только если задан `NEXT_PUBLIC_YM_ID`, и только после согласия в cookie-баннере.

## 9. Хостинг и деплой

- `Dockerfile` (multi-stage, Node LTS, `standalone`, непривилегированный пользователь).
- `docker-compose.yml`: приложение + Nginx (gzip/brotli, кеш статики `immutable` на год, HTTP→HTTPS) + certbot для Let's Encrypt.
- `deploy/deploy.sh`: сборка и перезапуск на VPS по SSH. Параметры (хост, пользователь, домен) — из переменных, не хардкодить.
- `docs/DEPLOY.md` — пошагово для человека: аренда VPS, DNS, первый запуск, обновление.
- Если Docker в локальной среде недоступен — просто напиши файлы и проверь их синтаксис; не устанавливай Docker сам.

## 10. Качество (критерии «готово»)

- `npm run check` = `typecheck` + `lint` + `test:e2e`, всё зелёное.
- Lighthouse (мобильный профиль) по `/`, `/istoriya`, `/lyudi`: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO = 100.
- axe: 0 нарушений уровня serious/critical.
- Core Web Vitals в лабе: LCP < 2,5 с, CLS < 0,05.
- JS на клиенте — минимум: клиентские компоненты только там, где есть интерактив (меню, лайтбокс, форма, счётчики).
- Скриншоты Playwright на ширинах 360, 768, 1280 для каждой страницы сохраняются в `screenshots/`. **Смотри их сам** после каждой фазы с вёрсткой и исправляй то, что выглядит плохо: наезды, пустоты, сломанные переносы, слишком мелкий текст на мобильном.
