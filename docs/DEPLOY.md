# Деплой сайта на VPS

Пошаговая инструкция для человека без глубокого опыта в Docker/Linux. Если что-то пошло не
так — не бойтесь, большинство шагов безопасно повторить ещё раз.

## 1. Аренда VPS и домен

1. Арендуйте VPS у российского провайдера (например, Timeweb Cloud, Selectel, REG.RU,
   Beget Cloud). Минимальные требования: 1 vCPU, 1–2 ГБ RAM, Ubuntu 22.04 или 24.04.
2. Купите домен (если ещё нет) у российского регистратора.
3. В панели управления доменом создайте **A-запись**, указывающую на IP-адрес VPS:
   ```
   @    A    <IP вашего VPS>
   www  A    <IP вашего VPS>
   ```
   DNS обновляется не мгновенно — иногда нужно подождать от нескольких минут до пары часов.
   Проверить, что всё заработало, можно командой `ping ваш-домен.ru` — она должна показать
   IP вашего сервера.

## 2. Подготовка сервера (один раз)

Подключитесь к серверу по SSH (`ssh root@<IP сервера>`) и установите Docker:

```bash
curl -fsSL https://get.docker.com | sh
```

Создайте отдельного пользователя для деплоя (не работайте под `root` постоянно):

```bash
adduser deploy
usermod -aG docker deploy
```

Разрешите этому пользователю вход по SSH-ключу (скопируйте свой публичный ключ в
`/home/deploy/.ssh/authorized_keys`), затем переключитесь на него: `su - deploy`.

## 3. Первый запуск

На сервере, под пользователем `deploy`:

```bash
git clone <адрес вашего репозитория> dina-site
cd dina-site
cp .env.example .env
nano .env   # заполните значения — см. ниже
```

### Что заполнить в `.env`

```
NEXT_PUBLIC_SITE_URL=https://ваш-домен.ru
NEXT_PUBLIC_YM_ID=              # id счётчика Яндекс.Метрики, необязательно
SMTP_HOST=smtp.yandex.ru        # или другой российский провайдер почты
SMTP_PORT=465
SMTP_USER=noreply@ваш-домен.ru
SMTP_PASS=пароль-от-почты
MAIL_FROM="Сайт «Дины» <noreply@ваш-домен.ru>"
MAIL_TO=куда-присылать-заявки@ваш-домен.ru
DEPLOY_HOST=<IP или домен сервера>
DEPLOY_USER=deploy
DEPLOY_DOMAIN=ваш-домен.ru
LETSENCRYPT_EMAIL=ваша-почта@example.ru   # для уведомлений от Let's Encrypt
```

Соберите образ приложения:

```bash
docker compose build
```

Получите SSL-сертификат (один раз — подробности в комментариях самого скрипта):

```bash
./deploy/init-letsencrypt.sh
```

Запустите весь стек:

```bash
docker compose up -d
```

Откройте `https://ваш-домен.ru` — сайт должен открыться с валидным замком браузера.

## 4. Обновление сайта (после первого запуска)

Дальше для каждого обновления (новый контент, фото, код) **с вашего компьютера**:

```bash
git push                 # если ещё не запушили изменения
./deploy/deploy.sh       # подключится по SSH, пересоберёт и перезапустит
```

`deploy/deploy.sh` берёт `DEPLOY_HOST`/`DEPLOY_USER` из вашего локального `.env` и подключается
по SSH к серверу, где делает `git pull`, пересобирает образ и перезапускает контейнеры.
Убедитесь, что у вас настроен SSH-доступ без пароля (по ключу) к серверу под пользователем
`DEPLOY_USER` — иначе скрипт будет спрашивать пароль при каждом запуске.

## 5. Автопродление сертификата

Контейнер `certbot` в `docker-compose.yml` уже настроен проверять и продлевать сертификат
каждые 12 часов в фоне (Let's Encrypt продлевает за 30 дней до истечения, этого достаточно,
дополнительно ничего настраивать не нужно). Если нужно продлить вручную:

```bash
docker compose run --rm certbot renew
docker compose exec nginx nginx -s reload
```

## 6. Полезные команды

```bash
docker compose ps                  # что сейчас запущено
docker compose logs -f app         # логи приложения (здесь же видны письма с формы,
                                    # если SMTP не настроен — см. docs/CONTENT_GUIDE.md)
docker compose logs -f nginx       # логи веб-сервера
docker compose restart app         # перезапустить только приложение
docker compose down                # остановить всё (данные сертификатов сохранятся в volume)
```

## Brotli (опционально)

Текущая конфигурация Nginx включает gzip — этого достаточно для хорошего сжатия текста,
CSS и JS. Brotli даёт чуть лучшее сжатие, но требует отдельного модуля, которого нет в
стандартном образе `nginx:alpine`. Если хотите добавить Brotli:

1. Замените образ `nginx:1.27-alpine` в `docker-compose.yml` на образ с уже собранным
   модулем brotli (например, поддерживаемые сборки из `docker.io/nginxinc` с
   `ngx_brotli` или аналогичные community-образы — проверьте актуальность и
   доверенность источника образа перед использованием в продакшене).
2. Добавьte в `docker/nginx/nginx.conf` внутри блока `http {}`:
   ```nginx
   brotli on;
   brotli_comp_level 5;
   brotli_types text/plain text/css application/javascript application/json image/svg+xml;
   ```
3. Пересоберите и перезапустите: `docker compose up -d --force-recreate nginx`.

## Что делать, если что-то не работает

- **Сайт не открывается вообще** — проверьте `docker compose ps`: все три сервиса должны
  быть `Up`. Если `app` падает — смотрите `docker compose logs app`.
- **Сертификат не выпускается** — убедитесь, что DNS уже указывает на сервер
  (`ping ваш-домен.ru`) и что порт 80 ничем не занят (`docker compose ps`, другой веб-сервер
  на сервере может конфликтовать — остановите его).
- **Форма не отправляет письма** — проверьте `SMTP_*` переменные в `.env` и
  `docker compose logs app` на предмет ошибок SMTP. Пока `SMTP_HOST` пуст, письма
  пишутся в этот же лог вместо отправки — это штатное поведение для проверки.
