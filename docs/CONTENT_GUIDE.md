# Как менять контент сайта (без программиста)

Весь текстовый контент сайта лежит в файлах `content/*.json` — это обычные текстовые файлы,
их можно открыть и отредактировать в любом текстовом редакторе (подойдёт даже Блокнот,
но удобнее — [VS Code](https://code.visualstudio.com/) или [Notepad++](https://notepad-plus-plus.org/)).

**Главное правило: после любого изменения в `content/` нужно пересобрать и перезапустить
сайт**, чтобы изменения появились (см. «Как применить изменения» в конце этого файла).

## Общие правила формата JSON

- Текст всегда в двойных кавычках: `"как тут"`.
- Если в тексте есть кавычки «ёлочки» — их использовать можно, они не ломают файл: `"Дина — «Пушкари»"`.
- После каждого значения, кроме последнего в списке, — запятая.
- Если факт не подтверждён и его не нужно показывать на сайте — пишите `null` (без кавычек).
  **Никогда не придумывайте значение вместо `null`** — на сайте оно просто не покажется, это нормально.
- Проверяйте файл на сайте [jsonlint.com](https://jsonlint.com/) перед тем как сохранить, если
  не уверены, что не сломали структуру (пропущенная запятая или кавычка — самая частая ошибка).

## Добавить фотографию

1. Откройте `content/photos.json`.
2. Найдите нужный слот по `id` (например, `"id": "hero-main"`) — там же указано имя файла:
   `"file": "hero-main.jpg"`.
3. Положите файл с ровно таким именем в папку `public/photos/`.
4. Если у фото есть автор/источник — укажите в поле `"credit"` этого слота, например:
   `"credit": "Фото: архив клуба"`. Если автор неизвестен — оставьте `null`.
5. Если есть подпись к фото — впишите в поле `"caption"`.
6. Пересоберите сайт. Фото появится автоматически везде, где используется этот слот
   (на главной, в истории, в галерее) — сайт сам покажет настоящее фото вместо
   типографической заглушки.

**Требования к файлам фото:** JPG или PNG, любое разрешение (сайт сам оптимизирует),
но лучше не меньше 1600px по длинной стороне для чёткости на больших экранах.

### Добавить новый слот в галерею «История в фотографиях»

1. В `content/photos.json` добавьте новый объект в массив `"slots"` (скопируйте
   структуру существующего и поменяйте `id`, `file`, `aspect`, `era`, `description`, `fallbackText`).
2. Добавьте этот `id` в список `"gallery" → "slotIds"`, если фото должно попасть в общую галерею.

## Изменить текст о клубе (слоган, история, «Дина сегодня»)

Откройте `content/club.json`:

- `"tagline"` — слоган под заголовком на главной.
- `"historyIntro"` — три абзаца краткой истории на главной (массив строк).
- `"today"` → `"title"` и `"text"` — блок «Дина сегодня».
- `"contacts"` — email, телефон, адрес, соцсети. Если поле `null` — на сайте просто не
  показывается соответствующая строка (так и задумано, это не ошибка).
- `"requisites"` — реквизиты юрлица для страницы «Политика конфиденциальности». Пока
  `null` — на странице политики показывается явная пометка-черновик вместо реквизитов.

**Важно:** не добавляйте сюда факты, которых нет в проверенных источниках (см.
`docs/research-notes.md`). Сайт сознательно не публикует неподтверждённые цифры.

## Добавить легенду клуба

1. Откройте `content/people.json`, массив `"legends"`.
2. Скопируйте один из существующих объектов, вставьте в конец массива перед закрывающей `]`,
   не забудьте запятую после предыдущего объекта.
3. Заполните поля:
   - `"id"` — короткий идентификатор латиницей без пробелов (например, `"petrov"`), используется
     как якорь ссылки `/lyudi#petrov`.
   - `"name"`, `"role"` — обязательны.
   - `"lifeYears"` (например, `"1970–2010"`) и `"yearsInClub"` — если неизвестны, оставьте `null`.
   - `"headline"`, `"text"` — короткое и развёрнутое описание.
   - `"featured"` — `true`, если легенда должна попасть в 6 карточек на главной странице
     (если уже есть 6 `featured: true`, сначала снимите этот флаг у кого-то другого).
   - `"photoSlot"` — id фотослота (добавьте его в `content/photos.json`, если это новый человек).
   - `"sources"` — ключи из `content/sources.json`, подтверждающие факты.
4. На странице `/lyudi` легенда появится автоматически со своим фото (или заглушкой),
   а на главной — если `featured: true`.

## Изменить трофеи или этапы истории

- `content/trophies.json` — список титулов. `"years"` — список годов, `"featured": true`
  означает «показывать в блоке „Масштаб“ на главной».
- `content/timeline.json` — 7 этапов истории на странице `/istoriya`. `"ghost"` — число или
  год, который показывается огромным полупрозрачным текстом рядом с заголовком этапа.

## Поменять почту для формы обращения

Откройте `.env` в корне проекта (если его нет — скопируйте `.env.example` и переименуйте
в `.env`) и укажите:

```
SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_USER=noreply@ваш-домен.ru
SMTP_PASS=пароль-от-почты
MAIL_FROM="Сайт «Дины» <noreply@ваш-домен.ru>"
MAIL_TO=куда-присылать-заявки@ваш-домен.ru
```

Пока `SMTP_HOST` не заполнен, письма с формы просто пишутся в лог сервера (сайт при этом
работает нормально, но писем на почту не будет).

## Как применить изменения

### Если сайт уже работает через Docker на сервере
Изменения в `content/*.json` требуют пересборки образа (это обычный текст, который Next.js
«запекает» в сборку). Проще всего:

```bash
git add content/ public/photos/
git commit -m "Обновление контента"
git push
```

а затем на сервере — `./deploy/deploy.sh` (см. `docs/DEPLOY.md`).

### Локально, чтобы посмотреть, что получилось
```bash
npm run dev
```
и откройте http://localhost:3000. После проверки `npm run build` должен пройти без ошибок —
это убедится, что JSON не сломан.
